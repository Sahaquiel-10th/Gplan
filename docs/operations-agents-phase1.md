# 经营助手第一期

本期实现：昨日亏损助手、销量与库存助手、商品经营诊断（系统 SKU 粒度），以及管理员成员授权、快捷操作和站内通知。SKU 智能组合与完整线上链接诊断留到下一期，需先补齐线上 SKU 组合映射、商品知识范围与平台流量／广告数据。

## 使用入口

管理后台 → 经营助手 → 创建一期助手。初始全部为草稿，不自动授权任何人，包括管理员。每个助手选择状态和解释模型，再逐人指定店铺、品牌；库存助手还必须指定仓库。保存后，授权成员在“智能体”中看到入口。

成本和利润随亏损助手权限开放，但只限该成员授权店铺、品牌（以及选择的仓库）。普通聊天与其他助手不继承该能力。管理员拥有配置权，不自动拥有经营报表读取权。普通智能体编辑器也增加“企业全部成员／指定成员内测”，指定成员模式禁用公开分享、通用知识检索与记忆。

## 权限与隔离

- 服务端只信任登录身份、公司及管理员存储的范围。报表不接受任意 SQL、工具名、成员身份或客户端数据范围。
- 业务助手使用独立报表与解释接口，普通聊天及公开分享接口拒绝其调用。
- 亏损整单金额只在该单所有明细的品牌都获授权时返回；未知品牌或混合未授权品牌的整单不返回。
- 库存严格限定仓库、品牌；销量同时限定店铺和仓库。共享仓库存量不代表某店铺独占库存。
- 解释仅发送本次授权报表、必要计算说明与本次快捷／自定义问题，最多取前200行。无全库 RAG、个人记忆、跨会话历史、联网或模型自由查询能力；解释保存在成员专属的经营快照中，不写入通用聊天记录和记忆。
- 缓存键包含公司、助手、成员、完整范围、口径版本和日期；最多2分钟／100份报表。权限变化后旧缓存不可访问，进行中的报表／解释返回前再次校验权限。
- 受限会话的列表、详情、归档响应、附件读取与保存记忆均检查权限；删除受限助手不把会话降级成普通会话。
- 配置变更记录成员、时间和版本，不记录原始业务数据。模型 token 使用单独计入用量记录。

## 计算口径 v1

### 亏损

统计北京时间所选日期的销售出库单，不冒充支付订单口径。预估毛利默认使用 `actual_payment - SUM(cost_amount) - delivery_cost`，服务费、仓储费可在后台纳入；`post_fee` 不作为实际运费重复扣除。退款、广告等未接入成本不计入，结果始终称为预估毛利。

目前抽样 RDS 的币种字段为空，默认按人民币暂估，并在计算说明展示；管理员可关闭该假设。明确为其他币种、必需成本／费用缺失、负数或套装成本层级不明的记录显示“待核算”。金额按分做确定性运算。备注出现补发等词只标记疑似，不自动排除；后台可配置经业务核实的单据类型编码。

最多核算1000张授权出库单，超过上限明确提示部分结果。费用字段含义还需客户抽样对账，不能把初始口径当作最终净利润。

### 库存

参考天数 = max(0, 当前可用库存) ÷ 近3日日均正向出库数量。可用库存 = 实物数量 − 锁定数量。关注线默认7天，目标默认30天；目标缺口 = max(0, 7日日均销量 × 目标天数 − 可用库存)，向上取整。

在途数量展示但不抵扣目标缺口，因为到货日期尚未接入。无近期销量不除零；负库存显示缺货；缺失或超过36小时的库存不输出确定天数。套装映射未核实的不计算风险。

这里只用授权店铺销量，共享库存也可能被其他店铺消耗，因此结果称为“参考天数”，不能作为全仓断货预测或自动采购数量。库存是当前快照，选择历史日期不会回放历史库存。

### 商品诊断

近7天销量与前7天比较；绝对变化达到50%标记关注。输出系统 SKU 的销量和出库销售额，不使用未接入的广告、曝光、转化数据解释原因。无上期销量时不计算增长率。库存／诊断均最多展示近7天销量前200个商品，超出时明确标记；没有销售记录的商品不在榜单中。

## 通知

进程每15分钟检查一次，北京时间08:00之后为已开放且已授权的成员检查昨天的报表。每个成员、助手、权限版本、日期最多生成一次通知；有需关注事项或数据待核实才提示。通知仅包含助手、日期和状态，点击后重新授权查询；已读状态持久化，撤销权限后隐藏旧通知。不发送钉钉消息。

## 部署

应用状态仍使用现有 app_state 存储，新增字段兼容旧数据，不需要手动创建业务配置表。使用现有 DATA_MYSQL_* 配置，仅对 RDS 经营表执行 SELECT，不调用万里牛接口。

真实 RDS 测试发现30天聚合容易选择全表扫描；当前实现按日使用时间索引查询，并以3路并发汇总。建议在应用服务器部署时执行幂等脚本：

```sh
node scripts/migrate-operations-index.mjs
```

脚本增加 `(company_id, shop_id, bill_date)` 索引，使用 `ALGORITHM=INPLACE, LOCK=NONE`，不改业务记录；现有数据库账号需要 ALTER 权限。应用重启后自动优先使用该索引。若未运行，仍可用按日时间索引回退，但首次30天查询较慢。缓存命中无需重新聚合。

部署流程：保留当前发行版及 app_state 备份，完成构建与测试，执行索引迁移，部署应用并重启进程。随后在后台创建草稿助手，仅给内测成员配置最小范围，验证后设为内测。回退时先在新后台停用经营助手，再回滚应用代码；新增索引可保留，不影响旧版。**旧版代码不认识新增成员权限，不能在保留受限助手开放状态的情况下回滚。**

## 验证记录

- `npm run build`：TypeScript 与生产构建。
- `npm run test:operations`：公司／成员／仓库边界、撤权与缓存标识、日期／金额边界、通知权限、公开分享、普通聊天绕过、旧会话与记忆隔离。
- 真实 RDS 只读试跑：141个店铺、36个品牌、4个仓库选项可读取；单个授权范围的三个报表均成功。亏损约0.15–0.30秒；未加新索引时，30天库存／商品首次查询约25–28秒。没有修改生产数据或部署线上应用。
- 测试仅证明代码及抽样链路可用；未证明所有历史同步完整、套装映射完整或费用口径已经得到客户确认。

## 2026-09-18 交互与历史分析更新

- 分析位于数据上方，长分析默认折叠。数据明细可收起，支持本次报表内搜索与10／20／50条分页；筛选显示各类数量，零匹配与整份报表无数据分别提示。搜索／分页不扩大原始查询上限。
- 通知改为独立页面，有全部／未读筛选和分页；侧栏仅显示入口与未读数。通知生成仍是每日08:00后每15分钟检查，不自动调用模型生成分析。
- 管理后台显示可编辑的默认分析提示词，成员授权可折叠，选项支持全选、选择搜索结果和清空。全选只存当前具体ID，不会自动授权后来新增的店铺或品牌。保存按钮处于配置页文档流底部，不悬浮。
- 按成员、公司、助手、完整权限版本和日期持久化报表与分析。再次查看复用已保存结果；刷新数据会重新查询并清空该日期旧分析，重新生成分析则只替换同一问题的答案。保留近90天快照，每个日期最近20份分析。存储沿用现有应用状态，发布不切换存储后端。
- 支持最长2000字自由提问，只提供当前获授权快照的前200行及汇总、口径给模型；不调用自由SQL、不引入通用知识库或记忆。前端筛选只影响表格显示，不改变模型分析的数据范围。
- 配置保存会递增版本并清理该助手旧快照；撤销权限、禁用账号或变更范围后不能读取已保存内容。生成开始及落盘时均重新检查权限，刷新期间完成的旧分析不能写入新快照。
- 新增持久化重载、缓存复用、主动重新生成、自由提问、版本变更、撤权及过期快照测试；浏览器检查分页、搜索、折叠、提示词、全选、通知页与手机布局。界面测试使用明确标记的演示数据。
