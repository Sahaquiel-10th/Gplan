# 企业支付宝多账户配置与锁定

## 当前交付范围

本次实现管理员多账户登记、RSA2 公钥/证书模式配置、加密持久化、为新公钥模式应用生成密钥、两个只读 API 的真实检测入口，以及配置模式锁定。

**不等于已接通真实账户。** 没有客户凭证时只做合成数据测试。当前尚未实现账单文件下载解析、资金明细落库、余额快照落库、定时同步、对账和智能体资金查询。这些需要一份真实账单跑通后逐项验收；页面固定标明未启用自动同步。

已有万里牛同步、客户对外数据 API 和经营驾驶舱不在本次修改范围。

## 服务器准备（非财务操作）

所有配置默认关闭。首次开放需由服务器维护人员在安全环境中配置以下环境变量，再按现有发布流程重启应用：

| 变量 | 含义 |
| --- | --- |
| `FINANCE_CREDENTIAL_MASTER_KEY` | 32 字节随机值的标准 Base64 编码；用于 AES-256-GCM。不得使用 JWT 密钥代替，不得提交 Git 或发到聊天。 |
| `FINANCE_CONFIG_ENABLED` | 显式为 `true` 才可配置；缺省关闭。 |
| `FINANCE_CONFIG_ADMIN_IDS` | 指定管理员的用户 ID，逗号分隔；不是用户名。空值不授权任何人。 |
| `FINANCE_CONFIG_EPOCH` | 本次维护窗口的独立标识，例如 `alipay-initial-20261030`。 |
| `FINANCE_CONFIG_EXPIRES_AT` | 带时区的 ISO 截止时间，必须位于未来24小时内；到期自动拒绝配置操作。 |

主密钥应存放于受限服务器环境或密钥管理服务，**不随账户密文一起存数据库**。单独加密备份并验证可恢复性；丢失主密钥无法恢复私钥。密钥轮换必须先解密旧数据、用新密钥重加密并验证，不能直接覆盖环境变量。

账户密文与状态沿用平台 `Store`：生产使用 MySQL 时存入 `gplan.app_state` 的独立 `alipayAccounts` 字段；JSON 模式仅供本地开发。大规模资金流水后续应落独立业务表，不能堆进该配置字段。密文绑定企业 ID、账户 ID、APP_ID 和配置修订号，交换密文不能跨账户解密。

仅在 HTTPS 的自有后台操作；现有管理员身份验证之后还会检查管理员实时状态、企业归属、配置窗口和指定管理员名单。前端不可改变这些服务器限制。

## 财务电脑操作

1. 客户企业支付宝开放平台创建自有应用并开通所需查询能力；不能用平台网页可访问代替 API 权限验证。
2. 在小象平台：管理后台 → 数据接入 → 企业支付宝账户 → 添加账户。
3. 填账户名称、支付宝认证企业主体、APP_ID 和签名模式。企业主体名称仅为登记信息，不是支付宝侧已核验身份；每套凭证必须由财务核对对应账号，查询不接收任意目标商户 ID。
4. 公钥模式：可导入本机已有私钥及支付宝公钥。对于尚未配置密钥的新应用，可点击“为新应用生成密钥”，服务器保管私钥，页面只提供应用公钥；复制到支付宝后，将支付宝公钥填回本平台保存。**应用公钥与支付宝公钥不可混用。**
5. 证书模式：导入现有的应用私钥、应用公钥证书、支付宝公钥证书、支付宝根证书。校验证书有效期及应用证书/私钥匹配；本次未提供证书申请或 CSR 生成流程。
6. 点击加密保存。编辑时留空保留已有私钥/同模式证书；保存后不回显、不下载私钥。上传仅在内存读取且有32KB限制，不把文件写到公共上传目录。
7. 点击检测只读接口，逐项看结果；每个账户间隔至少30秒，最多两个顺序请求、每次12秒超时。账户失败不影响其他账户。
8. 下一账户按同样步骤登记。页面不保存支付宝登录密码、验证码、Cookie。
9. 本轮配置结束，勾选确认后“完成并锁定”。服务器记录本企业对此维护窗口的持久锁，页面即隐藏配置、生成、保存和检测操作；没有网页解锁接口。

页面每30秒刷新配置窗口状态；过期或锁定后退出编辑并丢弃页面中的待提交密钥。提交失败时也清空密钥、证书输入，需要重新选择文件，以防明文在页面中长期停留。

## 检测口径

- `alipay.data.bill.balance.query`：只查询应用自身账户，不传 `bill_user_id` 等跨账户选择参数。只保存检测状态、时间和错误码；不把余额写入配置日志。
- `alipay.data.dataservice.bill.downloadurl.query`：查询上海时区昨日的 `signcustomer` 资金账单，要求 HTTPS 临时下载地址。获取地址不代表已经下载、解析、入库或对账；地址不返回浏览器、不持久化。
- 通过官方 `alipay-sdk`，强制 RSA2 和返回验签，正式网关地址固定；不提供自由 API 调试或自定义网关。
- `BILL_NOT_EXIST` 是“待账单复核”，不是“权限通过”也不是“昨日无交易”。本次检测日期固定昨日，历史账单复核后续实现。
- 原始 SDK 异常可能包含余额、请求签名或临时下载链接，统一转换为安全错误提示；不输出请求体、私钥或 SDK 原始异常到日志。
- 只读白名单只有上述两个方法。不能调用支付、转账、退款执行、投资、确认对账等资金操作。**私钥本身并非天然只读**：应在支付宝应用端仅开所需只读能力；应用不要与支付系统共用。

## 锁定、维护和后续同步

配置锁关闭的是“改变凭证和手动配置检测”的能力，不删除密文，也不会修改现有同步任务。未来自动同步应使用服务器内部的受控读取路径，不得复用对外配置接口或绕过企业数据权限。**本次无支付宝同步调度器，锁定后也不会凭空开始同步。**

需要维护时：由服务器维护人员更新窗口标识 `FINANCE_CONFIG_EPOCH`、未来24小时内的截止时间和指定管理员名单，显式开启并按既有流程重启。旧窗口在数据库中的锁不会因普通重启丢失。操作结束再次锁定，并建议服务器同时将 `FINANCE_CONFIG_ENABLED=false`。

## 路由与保护

均位于现有管理员会话保护之下，且服务内部再次核查用户实时状态及企业归属。

| 路由 | 配置锁关闭后 |
| --- | --- |
| `GET /api/admin/data-platform/alipay` | 可读取本企业状态，不提供私钥、支付宝公钥/证书、密文；锁定时也不提供应用公钥。 |
| `POST /api/admin/data-platform/alipay/accounts` | 拒绝 |
| `POST /api/admin/data-platform/alipay/accounts/generate-key` | 拒绝 |
| `PUT /api/admin/data-platform/alipay/accounts/:id` | 拒绝 |
| `POST /api/admin/data-platform/alipay/accounts/:id/check` | 拒绝，不请求支付宝 |
| `POST /api/admin/data-platform/alipay/lock` | 仅开放窗口内可锁定，没有反向解锁接口 |

旧 `/connectors/alipay/check` 返回410，避免环境变量存在就被误报为真实检测通过；旧 `/connectors/alipay/sync` 返回409，明确尚未启用同步。

配置变更、生成、检测与锁定记录账号 ID、操作者、企业和时间，不记密钥或资金明细。配置更新与检测完成时再次核查锁/用户状态，避免慢请求在锁定后写回。

## 本地验收

`npm run test:alipay-accounts`：加密/篡改/错密钥、跨企业隔离、角色与白名单、超时窗口、锁定持久化、锁后直接 HTTP 调用、密钥不回显、只读方法白名单、SDK 验签、能力状态分别测试。测试使用临时生成的合成密钥，不读取生产凭证、不请求真实支付宝账户。

`npm run build`：TypeScript 与生产前端构建。真实 API 权限与数据正确性必须在上线配置第一个客户账户后另行验收。
