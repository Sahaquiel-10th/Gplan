# 店铺评价回复

评价回复助手位于智能体列表。每位成员可以建立多份自己的店铺规则，先用模板或上传资料形成草稿，再通过试回复调整。工作台支持评价文字、截图识别、多个独立评价、候选回复、继续优化、手动编辑和复制。

## 使用流程

1. 在“我的店铺规则”选择模板或创建空白规则。东面山预设提供品牌语气与三个产品的起点；具体旧版规格和成分保留待核实状态。
2. 上传资料或粘贴文字，预览 AI 提取结果后应用到草稿。核对店铺、商品及可以公开引用的事实，保存规则。
3. 进入“开始回复”，选择规则和商品，粘贴原评价或上传截图。截图转成可编辑文字；批量评价各有独立的原文和商品选择。
4. 生成一至两条候选。可以复制、手动编辑，或选择一条继续优化。优化始终保留原评价与当前候选的上下文。
5. 临时修改只作用于当前候选。“记入店铺规则”先提出规则草案，确认后才保存为新版本。规则版本可还原，还原操作产生新版本。

## 配置与资料

配置包含品牌语气、长度、候选数量、称呼、表情、营销程度、署名收尾、回复目标、场景处理、禁用表达、售后口径、商品事实、示例和长期规则。常用项直接展示，细节放在更多配置中。

事实分为可引用、待核实、仅内部和禁用。自动识别的资料不会自行获得“可引用”状态。公开回复的模型输入仅包含所选商品及通用的可引用事实，其他商品和未批准资料不进入该输入；示例只指导表达方式，不充当产品事实依据。客户评价和上传文档中的指令视为数据。

截图识别使用实际能够发送图片的模型路径。识别出的文字随记录保留，后续优化不依赖模型再次看见截图。未识别出商品时需要运营确认，不从其他店铺补资料。

## 保存和权限

- 规则与回复记录绑定企业、所有者及专用智能体；普通成员可以创建自己的规则，其他账号不能读取、修改或导出。
- 默认个人私有。复制模板得到独立副本，修改不会影响模板或其他店铺。
- 店铺资料、历史版本和评价截图使用持久引用，避免被通用附件过期清理误删。正在引用的文件不能单独删除。
- 附件保留原有企业会话及来源智能体权限校验；访问权限变化后再次检查。
- 使用专用回复接口，不混入普通聊天的公司知识库、个人记忆或企业数据。
- 生成与优化在模型调用前保存幂等键和进行中状态。刷新通过记录恢复，不自动补发付费调用；重启时标记中断，保留已有结果。
- Skill 导出是可以复用的 Markdown 规则文件，不含 API 密钥、其他账号资料或私人回复历史。

## 接口

统一前缀 `/api/review-replies`，需要登录。`config` 提供可用模型状态和模板；`profiles` 管理配置、复制、版本、长期规则和导出；`analyze` 提炼资料；`recognize` 识别评价截图；`runs` 保存回复与优化历史。

持久集合为 `reviewReplyProfiles`、`reviewReplyRuns`。旧数据库加载时初始化为空，不重写旧智能体、主图任务或普通聊天数据。

## 验证

`npm run test:review-replies` 验证私人资料权限、事实状态、商品隔离、截图输入、多条候选、修改上下文、幂等请求、规则确认与版本、Skill 导出和中断恢复。模型替身用于检查请求和数据契约；真实文字质量需要运营用实际评价继续验收。
