# 电商主图与标题助手：第一版

## 产品约定

根据《会议录音文字.docx》后半段 00:16、09:14、13:34—16:40、21:39 附近讨论，以及 2026-10-21 本次确认实现：

- 在现有智能体列表展示内置「电商主图与标题助手」，打开专用工作页。
- 三步点选：商品资料 → 顾客与场景 → 表达重点。平台可选淘宝、天猫、京东、拼多多、抖音、快手、视频号、小红书和其他平台。
- 商品白底图必需，最多3张；参考图选传，最多3张。参考图只作布局与视觉参考。
- 上传后可识别清晰可见的包装文字，商品名称、品牌、规格可修改，卖点由用户勾选；识别失败仍可手动填写。
- 「明确方向」固定主要表达重点；「帮我探索」比较不同购买理由。两者都显示方案摘要与备选方向，无需另选是否展示。
- 默认5套，可选4套。每套有主图、标题、方案理由与标题解释。用户自行挑选，不宣称某套已验证效果最好。

## 执行流程

创建任务后，先调用理解模型分析商品、人群、渠道、关键词和可选参考图；再一次拟定4—5套画面方向与标题。方案整理完成后显示摘要，点击生成才开始作图。

作图严格串行，每次请求 `n=1`，且提示词要求只有一张完整画布。每次都重新使用原商品图，不把上一张生成结果作为下一张的商品依据。风格、排版、商品事实及用户选定的主要重点贯穿所有方案。

每张图片生成后立即保存，再调用理解模型检查商品外观、规格、图中文字及拼图问题。检查失败或无法判断时保留图片并显示需核对，不静默重绘。自动检查不等于平台审核或商业效果验证。

当前沿用现有作图接口，输出尺寸为1024×1024。平台选择影响策划上下文；本版没有声称接入各平台的实时上架规则、榜单、流量或用户画像。

## 保存、权限与恢复

- 任务元数据存入现有 app_state / JSON Store 的 `commerceJobs`，兼容原数据；图片落到现有 uploads 目录，远程图片地址也会下载保存。
- 任务按公司和成员隔离；普通聊天和公开智能体分享接口拒绝绕过专用流程。原图、生成图及历史版本都受附件权限检查保护。
- 使用中的原图、参考图和生成图不被普通24小时孤立附件清理删除。
- 单任务图片串行，进程最多同时运行2个任务。刷新或离开页面不影响任务；可从创作记录恢复。
- 创建请求带幂等标识，重复点击生成不会重复发起同批作图。重试仅处理指定图片，最多制作5次；重新生成成功后可下载旧版本。
- 服务重启时保留已保存图片，把未确认完成的工作标记为中断，由用户单独重试，避免静默重复计费请求。
- 单张下载和ZIP打包下载均读取已保存文件；ZIP含独立图片与标题说明文本。

## 模型与验证

自动选择现有启用且配置密钥的 OpenAI 协议理解模型（优先默认模型）及作图模型（优先同供应商）。现有 Anthropic 网关仅发送文本，故该流程不选择它做图片理解。没有所需模型时界面提示管理员配置。

自动化验证命令：

```sh
npm run build
npm run test:commerce
npm run test:operations
npm run test:workspace
```

商品创作测试涵盖多平台选项、参考图选传、方案数量、幂等提交、五次独立串行请求、部分失败与单张重试、原图复用、公司和成员隔离、附件保留、ZIP文件内容，以及服务重启后的结果恢复。

测试使用明确的本地模型替身，不证明实际供应商的商品保真、中文排版或主图效果。生产发布前应使用实际白底商品图检查真实作图模型输出。当前开发中本地 iCloud 占位文件读取不稳定，构建和浏览器验证使用独立副本；未修改原有数据同步及客户API的未提交工作。
