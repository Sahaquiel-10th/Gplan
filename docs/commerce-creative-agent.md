# 电商主图与标题助手：第一版

## 产品约定

根据《会议录音文字.docx》后半段 00:16、09:14、13:34—16:40、21:39 附近讨论，以及 2026-10-21 本次确认实现：

- 在现有智能体列表展示内置「电商主图与标题助手」，打开专用工作页。
- 四步点选：商品资料 → 主图模块 → 顾客与场景 → 表达重点。平台可选淘宝、天猫、京东、拼多多、抖音、快手、视频号、小红书和其他平台。
- 商品白底图必需，最多3张；参考图选传，最多3张。参考图只作布局与视觉参考。
- 上传后可识别清晰可见的包装文字，商品名称、品牌、规格可修改，卖点由用户勾选；识别失败仍可手动填写。
- 「明确方向」固定主要表达重点；「帮我探索」比较不同购买理由。两者都显示方案摘要与备选方向，无需另选是否展示。
- 默认5个方向，可选4或5个方向；方案接口同时兼容单方向任务。每套有主图、标题、方案理由与标题解释。用户自行挑选，不宣称某套已验证效果最好。

## 执行流程

创建任务后，先调用理解模型分析商品、人群、渠道、关键词和可选参考图；再一次拟定所选数量的画面方向与标题。方案整理完成后显示摘要，用户逐张选择参考图并点击「生成这张」才开始作图，不自动生成整组。

作图严格串行，每次请求 `n=1`，且提示词要求只有一张完整画布。每次都重新使用原商品图，不把上一张生成结果作为下一张的商品依据。风格、排版、商品事实及用户选定的主要重点贯穿所有方案。

每张图片生成后立即保存，再调用理解模型检查商品外观、规格、图中文字及拼图问题。检查失败或无法判断时保留图片并显示需核对，不静默重绘。自动检查不等于平台审核或商业效果验证。

沿用现有作图接口请求自动尺寸，提示模型生成对应画幅。保存时方图适配为1440×1440，配套竖图适配为宽1440、高1920，保持比例并保留完整画面；若模型原图尺寸不足或比例不符，会显示适配说明，不承诺放大能补出细节。平台选择影响策划上下文；本版没有声称接入各平台的实时上架规则、榜单、流量或用户画像。

## 保存、权限与恢复

- 任务元数据存入现有 app_state / JSON Store 的 `commerceJobs`，兼容原数据；图片落到现有 uploads 目录，远程图片地址也会下载保存。
- 任务按公司和成员隔离；普通聊天和公开智能体分享接口拒绝绕过专用流程。原图、生成图及历史版本都受附件权限检查保护。
- 使用中的原图、参考图和生成图不被普通24小时孤立附件清理删除。
- 单任务图片串行，进程最多同时运行2个任务。刷新或离开页面不影响任务；可从创作记录恢复。
- 创建请求带幂等标识，重复点击生成不会重复发起同批作图。重试仅处理指定图片，最多制作5次；重新生成成功后可下载旧版本。
- 服务重启时保留已保存图片，把未确认完成的工作标记为中断，由用户单独重试，避免静默重复计费请求。
- 单张下载和ZIP打包下载均读取已保存文件；ZIP含独立图片与标题说明文本。

## 模型与验证

自动选择现有启用且配置密钥的 OpenAI 协议理解模型（优先默认模型）及作图模型（优先同供应商）。现有 Anthropic 网关仅发送文本，故该流程不选择它做图片理解。没有所需模型时界面提示管理员配置。

自动化验证命令：

```sh
npm run build
npm run test:commerce
npm run test:operations
npm run test:workspace
```

商品创作测试涵盖多平台选项、参考图选传、方案数量、幂等提交、五次独立串行请求、部分失败与单张重试、原图复用、公司和成员隔离、附件保留、ZIP文件内容，以及服务重启后的结果恢复。

测试使用明确的本地模型替身，不证明实际供应商的商品保真、中文排版或主图效果。生产发布前应使用实际白底商品图检查真实作图模型输出。当前开发中本地 iCloud 占位文件读取不稳定，构建和浏览器验证使用独立副本；未修改原有数据同步及客户API的未提交工作。

## 参考图模块编辑（2026-10-22）

- 多张参考图中选择一张主要参考，单独识别整体风格、构图、原文、模块配置和近似区域。其他参考图供其他方向选择；每次实际作图仅发送本张选中的一张参考图。识别区域只用于界面定位，不向作图模型宣称精确图层坐标。
- 活动、商品、品牌、卖点、价格、优惠、赠品、服务、标识等固定模块与识别模块按类型合并；同类不同区域保留独立卡片，可增加自定义模块。
- 卡片展示原图内容及配置。勾选表示使用；取消勾选表示不展示；清空填写清除本次文字和模块素材，清空视觉配置清除位置及样式；恢复原图配置仅恢复位置和样式，不复制竞品文案。
- 默认只启用商品主体。参考原文不自动填入本次内容，也不进入策划的商品事实。非商品模块勾选后需填写本次内容或上传素材，清空后不会静默回退到参考文字。
- 可编辑文字、位置、样式、整体背景/配色和展示层级；支持最多3张模块素材，按输入顺序明确绑定模块。识别把握不足时提示核对，识别失败可手动添加。
- 商品、品牌、卖点及其他内容可请求文案建议，选中才填入。活动、价格、优惠、赠品、身份和服务承诺要求填写已确认内容，不提供自动编造入口。
- 模块配置直接进入分析、策划、每一张独立作图请求及生成后检查；已指定文案和配置在所有备选中一致，变化只发生在未指定内容。普通的主文案/辅助文案二字段限制仅用于旧任务。
- 旧任务没有composition时沿用原流程；新配置随任务持久化，草稿按成员保存在当前浏览器会话中。模块素材纳入附件所有权校验、任务保留和读取检查。
- 新接口：POST /api/commerce/reference/recognize、POST /api/commerce/modules/suggest。两者复用现有身份和成员权限检查，记录模型用量，并使用同一成员并发保护。
- 新增测试覆盖识别与素材越权、固定/动态合并、重复区域、清空校验、重新识别保留编辑、原文隔离、每张请求中的配置及素材映射。HTTP测试覆盖三张输入素材、串行独立制作、部分失败重试、附件保留、ZIP及重启恢复。浏览器验证使用明确的本地模型替身，真实模型保真、文字和布局仍需用商品实图验收。

## 小修小改（2026-10-22）

智能体列表新增独立「小修小改」卡片，打开直接上传一张图片、填写修改要求（最多1000字），一次提交只生成一张可下载的新版本。默认只调用图片编辑模型，不做商品识别、方案策划或额外的模型检查；没有聊天模型也可使用。

- 输入仅为当前原图与修改要求，提示词要求只改指定内容，尽量保留其他元素，不生成拼图或前后对比。小修小改请求使用自动尺寸并保留模型返回的原像素尺寸；主图助手按导出规格另行适配。自动尺寸由供应商和模型决定，不承诺保持原像素尺寸或未改区域逐像素不变。
- 任务使用既有commerceJobs保存，kind为image_edit，旧任务默认仍为product_creative。主图创作与修改记录分开展示，普通聊天和公开分享入口继续禁止绕过专用流程。
- 原图、修改结果和历史版本纳入原有附件保留及访问检查。其他成员、公司或已撤销授权的源任务图片不能作为编辑输入。
- 创建请求幂等，刷新不会重复提交；处理中的请求在重启后标记中断，手动重试才再次调用。成功结果立即保存；再次生成保留旧版本，重试失败也保留已有结果。
- 「在这版上继续改」明确将当前结果作为下一次输入，旧任务和版本保留在修改记录中。上传新图或修改要求可以创建新任务。
- 接口：GET /api/commerce/edit-config、POST /api/commerce/edits。结果、重试与附件下载复用原有受保护接口；GET /api/commerce/jobs?kind=image_edit只列本人的图片修改记录。

自动化测试覆盖单图单次调用、不依赖聊天模型、输入和源任务授权、幂等、防止重启后重复付费调用、失败保留、历史版本、继续修改、HTTP下载和记录恢复。浏览器验证使用明确标注的本地模型替身，实际修改精度仍需用真实图片模型验收。


## 运营访谈后的扩展（2026-10-29）

- 详情资料支持最多12张图片及20000字文字；分批上传兼容现有4附件限制。提炼出的卖点供核对勾选，关键词自动成为可点选候选，不作为搜索热度数据。原始详情及未选关键词不进入已确认策划事实。
- 关键词支持手填及XLSX/XLS/CSV导入，识别关键词和实际搜索热度列，忽略其他数值指标，最多100词；先展示12个报表词，其余展开查看。最多选20个词。无表格时使用详情和包装提取词。
- 标题按品牌前置、品类及真实属性、相关性优先、词根去重组织；淘宝／天猫采用本次运营约定的60长度单位预算（非ASCII为2，ASCII为1），其他平台不套用此预算。标题解释具体说明关键词依据，不编造流量和热度。
- 每个方向独立选择参考图，可明确不使用参考；默认在上传参考间轮换。只将选中的参考传给本张作图；换参考时清除从旧参考继承的布局和样式，保留用户实际改写的配置及确认文案。
- 主品、赠品、Logo素材和选定底图逐一标记输入角色；多视角不等于多件商品。提示明确禁止改包装、加泵头、复制主品充当赠品、沿用参考赠品。文字自动分组换行和安排主次，没有逐行样式表单。
- 在选中结果上直接续改，保留父任务及版本关系；配套3:4竖图沿用选定方案重新排版；SKU套版一次可提交1至12项，每项1至3张商品／组合图，每项单独调用、单独保存。三类派生任务都不重新进行整套策划。
- 商品资料保存可复用图片、详情和确认事实，不保存旧活动、优惠或创意组合；模板保存模块和视觉配置，套用时仍需核对本次商品内容。素材受成员、公司和智能体权限保护，并纳入附件保留与删除检查。
- 常规ZIP保持图片与标题说明；「交给视觉完善」另包含原始商品／参考／模块素材和需求说明。
- 回归覆盖选择生成、单参考隔离、重试保留、派生幂等与权限、SKU逐项素材、标题预算、关键词列识别及实际导出像素。测试模型验证流程，不等于真实模型商品保真度验收。
