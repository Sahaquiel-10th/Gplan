# 万里牛虚拟仓与订单/销售出库接口验证记录

验证日期：2026-08-20  
验证环境：客户万里牛 ERP 正式账号、万里牛官方签名 CLI  
数据保护：本文仅保留业务单号、商品、仓库编码及接口字段，不包含客户姓名、电话、地址等个人信息。

## 一、验证目的

验证万里牛“查询订单”或“查询销售出库单”接口返回的 `storage_code`，是否为虚拟仓编码，以及是否可以通过标准接口确定某笔订单具体扣减了哪个虚拟仓。

## 二、使用的官方接口

1. 虚拟仓库查询：`POST /erp/base/storage/virtual/warehouse/query`
2. 虚拟仓库库存查询：`POST /erp/open/inventory/virtual/inventory/query`
3. 实体仓库信息查询：`POST /erp/base/storage/query`
4. 查询订单：`POST /erp/opentrade/list/trades`
5. 查询销售出库单：`POST /erp/sale/stock/out/query`

## 三、验证结果

### 1. 虚拟仓真实编码

虚拟仓接口返回两个当前生效的虚拟仓：

| 虚拟仓编码 | 虚拟仓名称 | 状态 |
|---|---|---|
| `0001` | 薇诺娜奕页仓 | 已生效 |
| `0002` | 薇诺娜小象仓 | 已生效 |

### 2. 虚拟仓与实体仓存在编码冲突

实体仓接口同时返回：

| 实体仓编码 | 实体仓名称 | 状态 |
|---|---|---|
| `0001` | 仁和仓 | 启用 |
| `0002` | 仓库二部 | 禁用 |

因此 `0001`、`0002` 在虚拟仓和实体仓两套数据中代表不同仓库，单独看到编号无法判断它属于虚拟仓还是实体仓。

### 3. 使用虚拟仓编码查询订单

请求：

```json
{
  "modify_time": "2026-08-19 00:00:00",
  "end_time": "2026-08-20 23:59:59",
  "storage_code": "0002",
  "page": 1,
  "limit": 1,
  "is_split": false
}
```

万里牛接口原样返回：

```json
{
  "code": 1500,
  "message": "查询订单出错，原因：不存在编码为0002仓库"
}
```

这说明订单接口的 `storage_code` 查询条件没有把当前生效的虚拟仓 `0002` 识别为可查询订单仓库。

使用 `storage_code=0001` 时接口返回成功但没有订单。由于实体仓中也存在启用的 `0001`（仁和仓），该结果不能证明接口识别的是虚拟仓 `0001`。

### 4. 虚拟仓商品与真实出库单交叉验证

商品 `舒护修敏保湿面膜（单贴）` 同时存在于两个虚拟仓：

| 虚拟仓编码 | 虚拟库存 | 虚拟可用库存 |
|---|---:|---:|
| `0001` | 419 | 417 |
| `0002` | 1646 | 1591 |

该商品对应的真实销售出库单：

- 出库单号：`XC260820005811`
- 关联系统订单号：`XD260819038414`

调用销售出库单接口后返回：

| 字段 | 返回值 |
|---|---|
| `storage_code` | `CK001` |
| `storage_name` | 淘宝仓库 |
| 明细 `inventory_type` | `ZP` |

继续调用订单详情接口查询关联订单，返回：

| 字段 | 返回值 |
|---|---|
| `storage_code` | `CK001` |
| `storage_name` | 淘宝仓库 |
| 明细 `inventory_status` | 已出库 |

本次实际响应中，订单头只存在 `storage_code`、`storage_name` 两个仓库相关字段；订单明细只存在 `inventory_status`，未返回 `virtual_warehouse_code`、`warehouse_code` 或其他可识别虚拟仓的字段。

需要特别说明：商品同时存在于 `0001` 和 `0002` 两个虚拟仓，而订单和销售出库单只返回 `CK001`，因此仅凭该商品及出库记录，无法判断这笔订单具体扣减了 `0001` 还是 `0002`。

## 四、当前结论

基于本账号在 2026-08-20 的实际接口响应：

1. 标准订单接口和销售出库单接口返回的是实体履约仓编码 `CK001`，没有返回具体虚拟仓编码。
2. 虚拟仓编码与实体仓编码可能重复，编号本身没有全局唯一语义。
3. 商品存在于某虚拟仓，只能证明当前存在虚拟库存，不能证明某笔历史订单扣减了该虚拟仓。
4. 在缺少订单明细行到虚拟仓编码的直接字段时，系统只能通过关联店铺、SKU 和虚拟仓配置做推断，不能作为审计级事实。

## 五、请万里牛销售/技术明确回复

如果万里牛认为已有接口可以返回订单对应的虚拟仓，请提供以下任一项，以便复测：

1. 精确接口路径，例如 `/erp/.../...`；
2. 完整请求参数，特别是虚拟仓查询条件；
3. 返回虚拟仓编号的精确字段路径，例如 `data[].details[].virtual_warehouse_code`；
4. 一笔可复现的订单号及脱敏响应示例；
5. 明确说明该字段返回的是虚拟仓编码还是实体仓编码，以及两套编码重复时如何区分。

在没有上述信息前，“出库/订单接口会返回虚拟仓编号”与本次正式账号实测结果不一致。
