# 发票汇总助手

入口：智能体 → 财务工具 → 发票汇总助手。普通成员各自保留任务及原件，管理员不跨用户读取。

选择多文件、文件夹或 ZIP/RAR/7Z 后自动上传和处理。每批最多500个文件（含压缩包展开后的文件），单个100MB、总计500MB；单份PDF/多帧图最多100页，本批最多2000页；单压缩包展开最多250MB、嵌套最多3层。加密、缺分卷、损坏、特殊不支持的格式明确列出原因。

格式包括 PDF、JPG/PNG/WebP/GIF/TIFF/BMP/HEIC/HEIF/AVIF、OFD文字层、XML、TXT、DOCX、XLS/XLSX/CSV。扫描PDF逐页渲染并送入图片理解模型。无文本或特殊结构的OFD提示转成PDF，不声称能读取任意私有格式。配置使用现有启用的聊天模型，图片需要OpenAI兼容图片理解模型。

每份、每页独立保存。关闭页面不取消服务端任务；历史保留原件及识别字段，随时重新导出。服务重启将已开始但无保存结果的付费页标为中断，只在用户明确重试时调用；尚未开始的页继续处理。请求编号幂等，重试仅覆盖失败页。相同字节跳过识别，相同发票代码+号码+销货方只计一次。

金额以分保存；未知留空、红字保留负数、发票号码按文本保存。缺字段或金额不符标注待核对。导出沿用提供模板的单工作表、八列、列宽、颜色、冻结首五行及合计位置；数据行按数量扩展，备注显示来源和核对提示。模板资产去除了客户原有票据数据。失败文件同样进入备注，不隐去遗漏。缺总额或未处理完时总额留空；外币不与人民币合计。可校对后重新下载。

## 部署

`npm ci --ignore-scripts` 安装 PDF 渲染、原生 canvas 和 WASM 解压依赖；Node20+。invoiceWorker.mjs在独立进程内解析，90秒超时、声明内存上限、文件/页数/解压额度；压缩路径不映射宿主文件系统。

Nginx现有通用请求限制为10MB。仅在新域名的server内安装 `deploy/nginx-invoices-upload.conf`，允许发票上传110MB请求，其他路由限制不变。变更前备份、`nginx -t`成功后reload。前端按最多20个文件且约32MB分块上传，100MB单文件单独上传。

## 验证

`npm run test:invoices` 覆盖金额、号码、隔离权限、HTTP批量上传、真实ZIP解包、图片实际传入、OFD/XML解析、重复票、部分失败/重试、重启恢复、校对并发和准确模板导出。HTTP模型使用本地替身，证明流程及请求，不替代真实票据识别质量验证。浏览器使用隔离数据库，覆盖桌面/移动端、混合文件、下载、校对、刷新历史。

PDF渲染使用本地Noto Sans CJK简体中文字体作为缺失字体回退，内嵌子集字体通过原生canvas字体桥接加载，不联网取字体。字体来源 https://github.com/notofonts/noto-cjk ，许可证随资产保留。固定双页合成样票覆盖未嵌入中文字体与内嵌字体；上线前通过真实配置模型验证中文测试样票的买卖方、20位号码及100/6/106金额。
